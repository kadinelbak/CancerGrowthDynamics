Two speed-ups added 1 Nov 2026

  • Two-pass bootstrap. Every candidate gets the first 40 bootstrap replicates. A candidate that never comes within 2 BIC of the best in any of those 40 (the selection rule's own band), and is not the carried model, the original pick or the generating model, is dropped for the remaining 160. The kept candidates get all 200. A dropped candidate was picked in none of 40 replicates, so its true pick rate is below about 7.5% (95% bound, 3 / 40); the bootstrap report marks it as screened out. The selection stability of the kept models is computed on all 200, as before. Setting: bootstrap_screen in stages.toml, or BOOT_SCREEN; BOOT_SCREEN=0 turns it off.
  • Control results reused when nothing they read has changed. Each control step (14, 30, 60, 120 days and both sweeps) writes a fingerprint of its inputs: the control code and configs, the data, the package versions, each stage's carried model and its bootstrap draws, and the Ce0 crowding fit. The next run skips the step and keeps its outputs when the fingerprint matches. A refit that changes no carried model or draw costs no control time; any change reruns it. julia run_pipeline.jl --recompute-control (or CONTROL_FORCE=1) always reruns.

The first run after this change has no fingerprints yet, so it runs every control step once. Neither change has been timed yet; the estimates below assume about 45–65 of the 132 candidates pass the screen, based on how often each candidate came within 2 BIC of the best in the 28 Oct bootstrap.

How the estimates were made

  • The 28 Oct column is the old pipeline; the estimate column includes the two speed-ups above. Fresh-rerun estimates scale the measured times. The fit step of the last run was resumed (ZOO_RESUME=1, ZOO_REUSE_BOOT=1), so the bootstrap checkpoints that were already finished were reused. A run with nothing reused redoes every bootstrap replicate, which would have taken 3–4.5 h before the screen; with it, about half the bootstrap refits remain.
  • Times scale roughly with threads for fits, analyses, the control steps and the sweep. With 4 threads instead of 10, expect about 2–2.5× longer (now about 9–13 h, or 5–7 h with control reused).
  • A reduced run, BOOT_B=40 GSA_N=2048, cuts the bootstrap 5× and the Sobol samples 8×. The fit step drops to about 40–60 min and the whole run to about 4 h, which is dominated by the 120-day control.
  • Resume a stopped run with julia run_pipeline.jl --from <step>. Finished bootstrap groups are checkpointed in outputs/zoo_fits/boot_checkpoints and reused with ZOO_RESUME=1.
  • Counts of refits on 28 Oct: 400 point-fit runs + 26,400 bootstrap refits + 1,800 block-bootstrap refits + ≈ 620 profile refits + 22 validation refits ≈ 29,200 (now about 15,000–18,500 with the screen). The control runs are simulations and MPC optimisations, not model fits; each MPC run is re-optimised at every decision, which is why the longer runs cost far more than the 14-day one.
